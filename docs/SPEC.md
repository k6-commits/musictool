## 0. ひとことで

歌う・ハミングする・口笛を吹くだけで、音程を C / D / E（ドレミ）のノートに割り当て、ピアノロールで直して、MIDI として書き出せる作曲アプリ。

---

## 1. 背景と狙い

2026 年は Nada、HumTrack、AnySing、Hum2MIDI など、声→MIDI アプリの新規参入が相次いでいる。ただし有力どころの多くは iOS 専用で、Android は広告付きの小規模アプリが中心、ブラウザで使える本格的なものはほぼない（詳細は調査メモ）。

差別化の軸（案）:

1. **どこでも動く**: Web（PWA）で iPhone / Android / PC を一度にカバーする
2. **直しやすさ**: 「自動で完璧」を目指すより、怪しいノートを目立たせ、数タップで直せる UI にする
3. **表現を捨てない**: しゃくり・ビブラートをピッチベンド / MPE として残すオプション
4. **端末内処理**: オフラインで動き、音声を外に出さない
5. **日本語ユーザー向け**: ドレミ表記・移動ド、中央ドの C3 / C4 表記切り替え

## 3. 最新トレンドと採用方針

| トレンド | 内容 | 本アプリでの扱い |
|---|---|---|
| 2 段構えの音程検出 | 歌っている最中は軽量モデルで即表示し、止めたら高精度に解析し直す | **採用（中核）** |
| 小型ニューラル F0 | SwiftF0（2025、約 9.6 万パラメータ、CPU で CREPE の約 42 倍速、雑音に強い、MIT）、PESTO（2025、遅延 10 ms 未満、LGPL-3.0） | **SwiftF0 を第一候補**に、Phase 0 で比較 |
| ノート単位の歌声採譜 | ROSVOT（ACL 2024）、STARS（ACL 2025）、Basic Pitch（ピッチベンド出力） | 自前のノート分割＋Basic Pitch で比較。ROSVOT はライセンス確認後に検討 |
| 端末内推論 | ONNX Runtime Web（WASM / WebGPU）、Core ML、LiteRT | **採用**（MVP はサーバーなし） |
| 表現の保持 | MPE / MIDI 2.0（Windows が 2026-02 に正式対応） | Phase 3 でピッチベンド / MPE 書き出し |
| AI 伴奏・共創 | Logic Pro 12 の Chord ID と Session Players、Suno Studio 2.0 の MIDI 編集と AI チャット、Magenta RealTime 2 | Phase 2 はルールベースのコード提案、Phase 3 で AI アレンジ |
| 「AI に作らせない」・プライバシー訴求 | Nada は生成 AI 不使用を明言、HumTrack は録音を学習に使わないと明言 | **採用**: メロディは必ずユーザーのもの。録音を学習に使わない |
| 声→楽器の音色変換 | DDSP / RAVE / Neutone Morpho | Phase 3 の実験機能 |
| ビートボックス→ドラム | Dubler 2、TRIA（2025） | Phase 2。**特許調査が前提** |

## 4. 機能一覧

### 4.1 MVP（Phase 1）

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | 録音 | 録音ボタン、カウントイン（1 小節）、メトロノーム（BPM 40〜240、拍子 2/4・3/4・4/4・6/8）、入力レベルメーター、音割れ警告 |
| F-02 | リアルタイム音程表示 | 今の音名を大きく表示（例: `E4` / `ミ`）、セントのずれメーター（±50）、鍵盤の上にピッチの軌跡を描く |
| F-03 | 声域キャリブレーション | 初回に一番低い声・高い声を出してもらい、検出範囲を絞る（オクターブ誤検出を減らす） |
| F-04 | 入力モード | 歌声 / ハミング / 口笛。モードごとに検出範囲としきい値を切り替える（6.3 節） |
| F-05 | 自動ノート化 | 録音停止後に高精度解析してノート列を作る |
| F-06 | キー / スケール | 自動推定＋手動指定（メジャー / マイナー / ペンタトニック / ブルース / ドリアン / クロマチック）。スケール吸着の強さ 0〜100% |
| F-07 | クオンタイズ | グリッド 1/4〜1/32（3 連符あり）、強さ 0〜100%、スイング |
| F-08 | ピアノロール編集 | ノート上に音名を表示。移動 / 長さ変更 / 分割 / 結合 / 削除 / 追加。元の声のピッチ曲線を背景に重ねる。信頼度の低いノートに「要確認」表示。ノート長押しでその区間の元の声を再生。元に戻す / やり直し |
| F-09 | 再生 | 楽器選択（ピアノ / シンセリード / ストリングス / ベル / フルート / ベース）、元の声と楽器のバランス、ループ再生 |
| F-10 | 書き出し | MIDI（.mid、SMF Type 1）、WAV、共有シート。DAW ごとの取り込み手順を表示 |
| F-11 | プロジェクト保存 | 端末内に保存。一覧・名前変更・複製・削除。バックアップ書き出し（.zip） |
| F-12 | 表記設定 | 音名: 英語（C D E）/ ドレミ（固定ド）/ 移動ド（キー基準）。中央ド: C4（標準）/ C3（ヤマハ式） |

吸着とクオンタイズは**非破壊**とする。元の解析結果を残し、スライダーを戻せばいつでも元に戻る。手で直したノートは再解析やスライダー操作で上書きしない。

受け入れ基準（主要機能）:

- F-02: 静かな部屋で歌ったとき、入力から画面表示までの遅延が 50 ms 以下（目標）。定常音で音名表示がちらつかない
- F-05: 30 秒の録音を中位スマホで 3 秒以内に解析する。精度は 9 章の目標を満たす
- F-10: 書き出した .mid を GarageBand / Logic Pro / FL Studio / Ableton Live / Cubase / Studio One で開いて、テンポ・拍子・音程・長さが一致する

### 4.4 当面やらないこと

- 歌詞やテキストから曲を丸ごと生成する機能（Suno 型）。差別化の軸と合わず、権利面も不確実
- 和音（多声）の採譜。対象は単旋律の声に限る

## 6. 処理パイプライン

```
マイク(48kHz) ─▶ 前処理 ─┬─▶ [リアルタイム系] F0推定(16ms刻み) ─▶ 音名・軌跡の表示
                        │
                        └─▶ 録音バッファ ─▶ [解析系] F0再推定 → オクターブ誤り補正 → 調律ずれ補正
                                             → ノート分割 → キー推定 → スケール吸着
                                             → テンポ / クオンタイズ → 信頼度付与 → ノート列
```

### 6.1 入力

- `getUserMedia` で `echoCancellation` / `noiseSuppression` / `autoGainControl` を `false` にする（ブラウザの音声処理はピッチを歪めるため）。無効にできない端末では警告を出す
- AudioWorklet で取り込み、16 kHz モノラルに変換して Web Worker へ渡す
- 伴奏やメトロノームを鳴らしながら録る場合はヘッドホンを必須にする（スピーカーの音がマイクに回り込むため）。Bluetooth は遅延が大きいので有線を推奨する

### 6.2 リアルタイム音程検出

| 優先 | エンジン | 理由 |
|---|---|---|
| 1 | SwiftF0（MIT、ONNX、16 kHz、16 ms 刻み、約 47〜2094 Hz、信頼度つき） | 小さく速く、雑音に強い。ブラウザでの動作実績あり |
| 2 | PESTO（LGPL-3.0、ストリーミング対応、遅延 10 ms 未満） | さらに低遅延が必要な場合（MIDI コントローラーモードなど）。ライセンスに注意 |
| 3 | YIN / McLeod（純 DSP、AudioWorklet 内） | 低スペック端末向けと口笛モード |

- 推論は ONNX Runtime Web（WASM）で Web Worker 上で実行する。WebGPU は対応ブラウザで任意に使う
- 出力: フレームごとに `{ t, f0Hz, confidence }`

### 6.3 入力モード別の初期パラメータ

| モード | 検出範囲 | 有声しきい値 | 最短ノート | 備考 |
|---|---|---|---|---|
| 歌声 | 65〜1050 Hz（C2〜C6） | 0.5 | 80 ms | 声域キャリブレーション後は「声域 ±2 半音」に絞る |
| ハミング | 65〜700 Hz | 0.4 | 100 ms | 倍音が弱く信頼度が下がりやすいので、しきい値を下げる |
| 口笛 | 500〜4000 Hz | — | 60 ms | ほぼ純音なので DSP（FFT ピーク＋補間）で推定する。SwiftF0 の上限（約 2094 Hz）を超えるため。書き出し時は 1〜2 オクターブ下げる |

数値はすべて初期値で、Phase 0 の評価で調整する。

### 6.4 解析（録音停止後）

1. **F0 の確定**: リアルタイム時の結果を使い回さず、録音全体を同じ（または高精度な）エンジンで推定し直す。処理落ちしたフレームを補え、以降のステップで前後のフレームを使った平滑化ができる
2. **連続ピッチへの変換**: `p = 69 + 12 × log2(f0 / 440)`（小数部 = セント情報を保持）
3. **オクターブ誤り補正**: 声域外の値や、前後と 12 半音飛ぶ値を Viterbi（動的計画法）で抑える
4. **調律ずれ補正**: 安定区間の「最寄りの半音からのずれ」の円周平均を全体のずれとして差し引く。長いテイクでは 8 秒窓で追従する（歌っているうちに音程が下がっていく対策）。結果は「平均 +18¢ 高め」のようにユーザーにも見せる
5. **ノート分割**: 「無音 / 各半音の発音」を状態とする HMM を Viterbi で解く（pYIN / Tony 方式）。補助ルール:
   - 最短ノート長はモード別（6.3 節）
   - 同じ音の連続（「ラ・ラ・ラ」）は、音量の谷（6 dB 以上）かオンセット検出で分ける
   - ビブラート（±50¢ 程度）では分けない（ヒステリシスをかける）
6. **ノートの音高**: 安定区間（頭と尻の 20% を除く）のピッチの中央値を丸める
7. **ベロシティ**: ノート区間の RMS（-50〜-10 dBFS）を 20〜110 に写像する（初期値）
8. **キー推定**: 音の長さで重み付けした音高ヒストグラムと、Krumhansl–Kessler のキープロファイルの相関を取る。上位 2 候補（平行調など）を出し、ユーザーが選べるようにする
9. **スケール吸着**（強さ s = 0〜1）:
   - s = 0: 半音に丸めるだけ（クロマチック）
   - s = 1: 必ず最寄りのスケール音にする
   - その間: スケール外の音は「スケール音までの距離 ≤ 0.5 + 0.5s 半音」のときだけ吸着する
10. **テンポ**: メトロノームモードでは既知。フリーモード（Phase 2）では、オンセット強度の自己相関で BPM 候補（60〜180）を出し、動的計画法のビートトラッキングで小節頭を決める
11. **クオンタイズ**（強さ q = 0〜1）: 開始位置 `t' = t + q × (最寄りグリッド − t)`。終了位置も同様に寄せる。「次の音まで伸ばす（レガート）」オプションあり
12. **信頼度**: `F0 信頼度の平均 × ピッチの安定度 × 長さ係数` で 0〜1 を出し、0.6 未満を「要確認」にする（初期案）

### 6.5 高精度オプション

- **Basic Pitch**（Apache-2.0、ピッチベンド出力、TypeScript 版あり）で再解析し、自前の分割結果と比べて良い方を採用する（Phase 0 で比較）
- **サーバー解析**（任意・明示的なオプトイン、Phase 3 以降）: ROSVOT などの重いモデル。公開されている学習済みモデルは非商用データ（M4Singer、CC BY-NC-SA 4.0）で学習されているため、使う場合は自前データで学習し直す

### 6.6 コード提案（Phase 2）

- 小節（または半小節）ごとに、メロディの各音を「長さ × 拍の強さ」で重み付けする
- 各ダイアトニックコード（I, ii, iii, IV, V, vi, vii°、V7、セカンダリードミナントは任意）について、構成音とメロディの一致度でスコアを付ける
- よく使われる進行（V→I、IV→V、ii→V など）の遷移しやすさと組み合わせて Viterbi で最適な進行を求め、小節ごとに上位 3 候補を提示する
- ルールベースなので結果が説明でき、ライセンスの問題もない。AI モデルは Phase 3 で追加する

### 6.7 再生

- Tone.js（MIT）と、ライセンスがクリアなサンプル音源（自作または CC0）を使う
- 元の声と楽器をミックスして再生する

## 7. データモデル

```ts
type ScaleMode =
  | 'major' | 'minor' | 'majorPentatonic' | 'minorPentatonic'
  | 'blues' | 'dorian' | 'chromatic';

interface Project {
  id: string;
  name: string;
  createdAt: string;               // ISO 8601
  updatedAt: string;
  bpm: number;                     // 40〜240
  timeSignature: [number, number]; // 例: [4, 4]
  key: { tonic: number; mode: ScaleMode }; // tonic: 0=C … 11=B
  ppq: 480;
  snapStrength: number;            // 0〜1（スケール吸着）
  quantize: { grid: string; strength: number; swing: number };
  tracks: Track[];
}

interface Track {
  id: string;
  kind: 'melody' | 'chords' | 'bass' | 'drums';
  name: string;
  instrument: string;  // 内部音色 ID
  gmProgram: number;   // 0〜127（MIDI 書き出し用）
  channel: number;     // 0〜15（ドラムは 9）
  muted: boolean;
  notes: Note[];
  takes: Take[];
}

interface Take {
  id: string;
  audioRef: string;    // IndexedDB の Blob キー
  sampleRate: number;
  inputMode: 'sing' | 'hum' | 'whistle' | 'beatbox';
  f0Ref?: string;      // F0 フレーム列（Float32Array）の保存キー
  tuningOffsetCents: number;
  recordedAt: string;
}

interface Note {
  id: string;
  pitch: number;          // MIDI ノート番号（60 = C4）
  startTick: number;
  durationTicks: number;
  velocity: number;       // 1〜127
  confidence: number;     // 0〜1（「要確認」表示に使う）
  raw?: {                 // 吸着・クオンタイズ前の解析結果（非破壊編集用）
    pitch: number;        // 小数つき半音
    startSec: number;
    endSec: number;
  };
  bend?: { tick: number; cents: number }[]; // 表現付き書き出し用（Phase 3）
  sourceTakeId?: string;
  edited: boolean;        // 手で直したノートは再解析・スライダー操作で上書きしない
}
```

## 8. MIDI 書き出し仕様

| 項目 | 内容 |
|---|---|
| 形式 | SMF Type 1、分解能 480 PPQ |
| トラック 0 | テンポ（FF 51）、拍子（FF 58）、調号（FF 59）、曲名 |
| トラック 1〜 | 各トラック名（FF 03）、Program Change、ノートオン / オフ、ベロシティ |
| チャンネル | メロディ = ch1、ドラム = ch10 |
| ファイル名 | `{プロジェクト名}_{YYYYMMDD-HHmm}.mid` |

音色と GM 番号の対応（1 始まり表記）:

| 楽器 | GM 番号 |
|---|---|
| ピアノ | 1 Acoustic Grand Piano |
| ベル | 10 Glockenspiel |
| ベース | 33 Acoustic Bass |
| ストリングス | 49 String Ensemble 1 |
| フルート | 74 Flute |
| シンセリード | 82 Lead 2 (sawtooth) |

表現付き書き出し（Phase 3）:

- **ピッチベンド**: RPN 0 でベンド幅を ±2 半音に設定し、ノートごとのピッチ曲線をピッチベンドで書く（単旋律なので 1 チャンネルで足りる）
- **MPE**: MCM（RPN 6）でゾーンを設定し、1 音ごとにチャンネル 2〜16 を割り当てる。ベンド幅は ±48 半音
- **MIDI 2.0 Clip File**: DAW の対応が広がったら追加する

## 9. 非機能要件

| 項目 | 目標 |
|---|---|
| リアルタイム表示の遅延 | 入力から描画まで 50 ms 以下（目標）、100 ms 以下（上限） |

| 精度（MVP リリース判定） | 自社テストセット（静かな環境・メトロノームあり）で、ノート F1 ≥ 0.80（オンセット ±50 ms・音高 ±50¢）、オクターブ誤り率 ≤ 2%。数値は Phase 0 の結果を見て見直す |
| オフライン | PWA として、録音から書き出しまでオフラインで動く |

| 対応環境 | iOS Safari 17 以降、Android Chrome 最新 2 版、デスクトップ Chrome / Edge / Firefox / Safari の最新版 |
| アクセシビリティ | 色だけに頼らない（「要確認」は色＋アイコン）。主要操作はキーボードでも可能 |
| 言語 | 日本語 / 英語 |

## 10. 技術スタック（推奨）

**推奨: Web（PWA）ファースト。** 理由: 1 つのコードで iPhone / Android / PC をカバーでき、競合が手薄な Android と PC にも届く。ストア審査がなく試作の回転が速い。後から Capacitor などでストア配布もできる。

弱点と対処:

- iOS Safari は Web MIDI に非対応 → MIDI はファイル書き出しで渡す。リアルタイム MIDI 出力はネイティブ版（Phase 3）で対応
- AUv3 プラグインは作れない → ネイティブ版で対応
- iOS の PWA はストレージが消されることがある → バックアップ書き出しと永続ストレージの要求（`navigator.storage.persist()`）

| 用途 | 採用候補 |
|---|---|
| 言語・ビルド | TypeScript、Vite |
| UI | React、PWA（Workbox） |
| 描画 | Canvas 2D（ピアノロール・ピッチ軌跡） |
| 音声 | Web Audio API、AudioWorklet |
| 推論 | onnxruntime-web（WASM、将来 WebGPU）、Web Worker |
| 音楽理論 | Tonal（MIT） |
| MIDI ファイル | @tonejs/midi（MIT）または自前実装 |
| 音源 | Tone.js（MIT） |
| 保存 | IndexedDB |
| テスト | Vitest（解析アルゴリズムは純関数にして単体テスト）、Playwright（Chromium の偽マイク入力 `--use-file-for-fake-audio-capture` に WAV を流して E2E） |
| 精度評価 | Python + mir_eval（ノート F1） |

ディレクトリ構成（案）:

```
src/
  audio/        マイク入力・AudioWorklet・再生
  pitch/        F0 エンジン（SwiftF0 / YIN）
  transcribe/   ノート分割・調律補正・キー推定・吸着・クオンタイズ（純関数）
  midi/         SMF 書き出し
  ui/           画面・ピアノロール
  store/        プロジェクト保存（IndexedDB）
public/models/  ONNX モデル
eval/           精度評価スクリプトとテストセットの正解 MIDI
```

## 12. 評価計画

- **テストセット**: 自社で収録する（歌声 / ハミング / 口笛 × 声の高い人・低い人 × 静か / 雑音あり、各 10〜20 フレーズ）。正解 MIDI は手で作る
- **公開データ**: HumTrans、MIR-1K など（ライセンスの範囲内で評価のみに使う）
- **指標**: フレーム単位の RPA / RCA、ノート F1（mir_eval）、オクターブ誤り率、解析時間、体感遅延
- **比較対象**: SwiftF0 / PESTO / YIN / Basic Pitch、および競合アプリ（Nada、AnySing、Hum2MIDI）に同じ歌を入れた結果

## 15. リスクと対策

| リスク | 対策 |
|---|---|
| iOS Safari が Web MIDI 非対応 | MIDI はファイルで渡す。リアルタイム出力はネイティブ版で |
| ブラウザの自動音量調整・ノイズ除去でピッチが歪む | 無効化を指定し、効かない端末では警告 |

| ハミングのオクターブ誤り | 声域キャリブレーション＋Viterbi |
| 歌っているうちに音程がずれていく | 調律ずれの追従補正 |
| 学習済みモデル・データのライセンス | 11 章の表で採用前に確認 |
| ビートボックス採譜の特許 | F-24 の実装前に調査 |
| PWA のデータが消える | バックアップ書き出し、永続ストレージの要求 |
