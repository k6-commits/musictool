# musictool 試作（Phase 0）

歌う（またはスマホの録音ファイルを開く）→ 音程を検出 → ノート（C / D / E…）に割り当て → ピアノロールで直す → MIDI に書き出す、までが動く試作です。画面は [デザイン](../docs/design.md) の「PC 02 録音・編集」をもとにしています。

- claude.ai で開く: https://claude.ai/artifact/MwgWYbftrod7iuYvyjep5J （非公開。共有はページの Share メニューから）
  - claude.ai 上ではマイクが使えないので、**音声ファイルを開く**か**内蔵サンプル**で試せます。保存は ZIP（中に .mid / .wav）
- マイクで歌うにはローカルで動かします（下記）

## ローカルで動かす

Node.js 22 以上が必要です。

```bash
cd web
npm install
npm run dev
```

ブラウザで http://localhost:5173 を開きます（PC の Chrome / Edge / Safari / Firefox）。localhost なのでマイクが使えます。

1. ●（または R キー）を押すと 4 拍のカウントのあと録音が始まります。歌うと鍵盤が光り、声の線とノートがその場で描かれます
2. もう一度 ● で停止すると解析してノートになります
3. 黄色の「!」は自信のない音です。右の「確認」から開き、鍵盤の形の候補から選びます（↑↓ キーでも半音ずつ動かせます）
4. SCALE つまみでキーの音に寄せる強さ、GRID つまみでタイミングをそろえる強さを変えます（元の解析結果は残るので何度でも戻せます）
5. 「書き出す」→ MIDI ＋ 声（.zip）/ MIDI（.mid）/ 声（.wav）。MIDI と WAV はどちらも 1 小節目の頭から始まるので、DAW の 1 小節目に置けばそろいます

フォルダのボタンかドラッグ＆ドロップで、スマホのボイスメモなどの音声ファイル（wav / mp3 / m4a など、6 分まで）も読み込めます。クリックなしで録った音声は、最初の音を 1 小節目の頭にしてテンポを推定します。

| キー | 操作 |
|---|---|
| R | 録音 / 停止 |
| Space | 再生 / 停止 |
| Home | 先頭へ |
| ↑ ↓ | 選んだノートを半音上げる / 下げる |
| ← → | 前 / 次のノートを選ぶ |
| Delete | 選んだノートを削除 |
| ⌘Z / Ctrl+Z | 元に戻す |
| ⌘E / Ctrl+E | 書き出し |

設定（つまみのアイコン）: 音名の表記（C D E / ドレミ）、中央のド（C3 / C4 / C5）、入力（歌声 / ハミング / 口笛）、遅れ補正、計測値（解析速度・有声率・チューニングのずれ・遅れ）。

## しくみ

```
マイク（自動音量調整・ノイズ除去はオフ）/ 音声ファイル
  → 16 kHz にリサンプル（窓付き sinc）
  → YIN で 16 ms ごとに基本周波数と確からしさ
  → ノート分割（src/transcribe/segment.ts）
      ・小さい音・自信の低いフレームを除外
      ・オクターブの飛びを近くの中央値に合わせて修正
      ・歌い手全体の音程のずれ（例: 全体に 15 セント高い）を推定して差し引く
      ・約 250 ms の中央値から 0.7 半音以上、3 フレーム続いたら次の音（ビブラートでは切れない）
      ・同じ高さの言い直しは音量の谷で分ける。息っぽい無音程は数フレームまで許す
      ・音高 = 中央 60% の中央値。半音の境目に近い音・揺れの大きい音・短すぎる音に「!」
  → キー推定（Krumhansl のプロファイル）、スケールへの吸着とクオンタイズ（元データは変えない）
  → MIDI（SMF タイプ 1・480 PPQ・テンポ / 拍子 / 調号つき）と WAV（16 bit）
```

録音中は同じ処理をその場で回して、声の線と確定したノートを表示します。録音の頭合わせは、クリックを鳴らした時刻と AudioWorklet が受け取ったフレーム番号から計算し、出力・入力の遅れを足しています（設定で手動補正もできます）。

## テストと計測

```bash
npm test          # 単体テスト（39 件）
npm run typecheck # 型チェック
npm run e2e       # ビルドして Chromium で通しテスト（27 項目）
npm run eval      # 合成音声で精度を測る
```

- `npm run e2e` は Chromium の疑似マイクに合成した歌声を流し、録音 → ノート → MIDI 書き出し → MIDI を読み直して照合、ファイル読み込み、ノートの修正と元に戻す、claude.ai 上と同じ条件（マイクなし・ZIP 保存）までを確かめます。画面のスクリーンショットは `e2e/out/` に出ます
- `npm run eval` の結果（2026-11-09、合成音声 12 条件・各 17 音）:

| 条件 | 正解 | F1 | 音の頭のずれ |
|---|---|---|---|
| テノール / バス / アルト / ソプラノ | 17/17 | 1.00 | 5〜10 ms |
| 全体に +35 / −40 セントずれ | 17/17 | 1.00 | 9 ms |
| 大きなビブラート（±60 セント） | 17/17 | 1.00 | 9 ms |
| 雑音 −25 dB / −18 dB | 17/17 | 1.00 | 5〜7 ms |
| 速い（150 BPM）/ ハミング / 口笛 | 17/17 | 1.00 | 6〜7 ms |

解析は 16 ms の音に対して 0.3 ms ほど（実時間の約 50 倍の速さ）。

**注意: これは合成した声での数字です。** 本物の声（子音、息、声の裏返り、部屋の響き）ではもっと下がるはずで、実際の録音での評価が次の課題です。

## ファイル構成

```
src/
  main.ts              画面の状態と操作
  dsp/                 リサンプル・YIN・ピッチ追跡（まとめて / その場で）
  transcribe/          ノート分割・並べ替え（吸着・クオンタイズ）・テンポ推定・採点
  music/               音名・スケール・キー推定
  audio/               マイク入力・再生（簡易シンセ・メトロノーム）・WAV
  midi/smf.ts          MIDI ファイルの書き出し
  ui/                  ピアノロール（canvas）・つまみ
  synth/voice.ts       合成の歌声（サンプルとテスト用）
  app/files.ts         書き出しファイルと ZIP
  body.html, styles.css
scripts/               build（1 ファイルの HTML に）・dev サーバー・eval
tests/                 単体テスト（vitest）
e2e/                   Chromium の通しテスト
eval/                  合成音声での精度計測
```

`npm run build` で `dist/index.html`（そのまま開ける 1 ファイル）と `dist/artifact.html`（claude.ai 用）ができます。
